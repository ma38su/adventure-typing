## 1. 役割と優先順位

本書は、3Dシーン制作ブリーフの画面目標をWebGLで実現するための補足文書である。レンダラー、地形、マテリアル、カメラ制御の実装候補を扱うが、制作範囲、構図、植生、画風、完成条件を変更しない。

参照時の優先順位は次の通り。

1. `docs/3d-scene-brief-meadow-to-forest.md`: 当該区間の画面仕様
2. `docs/story-bible.md`: 世界観、地理、物語上の正史
3. `docs/game-design.md`: タイピング体験、UI、アクセシビリティ
4. 本書: 上記を実現するための技術検討

`artwork/renderer-prototypes/watercolor-journey-renderer.html` は、WebGL、簡略化した樹木、水彩テクスチャ、紙目、距離霧などをブラウザで試すための**技術試作**である。草原から小川までの完成リファレンスでも、承認済みグレーボックスでもない。試作の現状と本書または正本が食い違う場合は、正本と本書に沿って作り直し、試作の実装を正当化の根拠にしない。

## 2. 対象体験と空間構成

対象は、`花の草原 → 林縁手前 → 最初の成木前 → 成木通過 → 森内部 → 小川手前`を一本のルートとして歩く同一3D空間である。森内部だけを作る仕様ではない。背景画像の交換、クロスフェード、暗転、霧の壁、ポータルで土地を切り替えない。

近景3Dと中遠景2.5Dは、次のように同じ空間へ配置してよい。

1. 地形: 草原から小川まで起伏が連続する地形メッシュ。
2. 獣道: 別の長方形メッシュを置かず、地形上の踏圧、土色、草・落ち葉の密度で表す。
3. 近景: 花、幹、根、苔岩、倒木、道しるべ、橋を簡略化した3Dモデルで表示する。
4. 中景: 若木、低木、シダ、草を透過板または簡略メッシュで重ねる。
5. 遠景: 遠い山、林縁、樹冠の大きな水彩面を3D空間へ置き、移動視差と距離霧で空間内に存在させる。
6. 画面処理: 紙目を画面全体へ一度だけ重ね、水彩のにじみは輪郭付近と色境界に限定する。

## 3. 10秒・6コマと旅座標

約10秒の自動再生は品質確認用の短縮デモであり、本番の所要時間ではない。空間上の位置は、ルートの正規化弧長座標 `s = 0〜1` で定義する。グレーボックスでは正本の6コマを次の `s` へ対応させ、各位置のスクリーンショットを提出する。値は実装上の初期目安であり、画面確認で調整してよいが、場面を欠落させない。

| 時間 | デモの `journeyProgress` | 空間位置 `s` | 場所 | 実装上の必須要素 |
|---:|---:|---:|---|---|
| 0.0秒 | 0.00 | 0.00 | 花の草原 | 細い踏み跡、広い空、少数の花、遠景の森と山 |
| 2.0秒 | 0.20 | 0.20 | 林縁手前 | 道際へ入る若木・低木、減り始める花 |
| 4.0秒 | 0.40 | 0.40 | 最初の成木前 | 近景の幹、落ち葉・苔が混ざる地面 |
| 5.5秒 | 0.55 | 0.55 | 森の入口 | 成木の間を実際に通過し、頭上を覆い始める樹冠 |
| 7.5秒 | 0.75 | 0.75 | 森内部 | 高木、若木、低木、草本、林床の5層 |
| 10.0秒 | 1.00 | 1.00 | 小川手前 | 細い木橋、水面、橋の先の明るい抜け、遠い山の気配 |

上表は10秒デモの検査用対応表である。デモでは `journeyProgress = time / 10秒` とし、表のアンカーを通る単調な `s = routeMapping(journeyProgress)` を明示的に実装する。成木通過の前後で速度を緩める場合は、アンカー間の曲線内で減速と回復を行い、表の時刻と `s` を変えない。本番では所要時間が異なっても同じ `routeMapping` を使う。時間、入力進捗 `journeyProgress`、空間位置 `s` は別の量であり、地形・幅・植生などの空間仕様を時刻や `journeyProgress` で直接定義しない。

カメラは旅座標に沿う緩い曲線から位置と注視点を求める。地上約1.5m、35mm換算約28〜35mm相当を基準とし、機械的な中央直進を避ける。冒頭は進行を感じやすくし、成木通過では景色を読めるよう速度曲線を少し緩める。

橋手前の `s = 0.82〜1.00` を重点検査区間とする。特に `s = 0.82〜0.94` は橋へ近づく森内部の獣道、`s = 0.94〜1.00` は橋への取り付きとして扱う。橋そのものの通行幅へ合わせるために直前だけ不自然に絞らず、`s = 0.55` 以降の森の入口から連続的に狭めておく。

## 4. 地形、土地の遷移、獣道

- 基準地形は高分割の連続メッシュとし、中央を安全で緩やか、左右と樹木の根元を高くする。
- 高低差は歩行の読解を妨げない範囲に抑え、カメラ高は地形高へ追従させる。
- 草原では幅約2.2〜2.5m、林縁では約1.8〜2.2m、森内部では約1.5〜1.8mへ踏み跡を徐々に細くする。
- 道端は花、草、落ち葉、露出根、苔岩で不規則に欠かし、直線的な境界を見せない。
- 地面、植生、光、霧、水音などの変化開始位置をずらし、土地の境界線を作らない。
- 木漏れ日は細かな葉形シャドウではなく、大きな柔らかい明色の筆致として扱う。

土地別マテリアルと論理レイヤー:

| 対象 | 内容 |
|---|---|
| `meadow-ground` | 淡い黄緑と生成りの大きな水彩面 |
| `forest-floor` | 翡翠、苔、落ち葉の大きな面。森へ進むほど比率を増やす |
| `foot-trail` | 暖かな土色。草原から林床まで連続し、輪郭を不規則に欠かす |
| `bark-light` / `bark-dark` | 岩絵具風の色むら。写真樹皮にしない |
| `leaf-light` / `leaf-mid` / `leaf-shadow` | 葉群単位の3色 |
| `moss` | 細粒ノイズではなく面として読める黄緑 |
| `water` | 青緑の透明感と少数の明るい筆致 |
| `bridge-wood` | 暖かい木色。過度な木目を避ける |

地面は `base wash`、`trail mask`、草原の草花、`forest litter`、`edge breakup`、`light wash` を論理レイヤーとして持ち、旅座標に応じた土地の変化を連続的に作る。地面テクスチャは短周期のタイリングを避ける。

### 中心線と幅の実装契約

ルートは、ワールド座標上の一本のスプラインと、その弧長で正規化したルート座標 `s = 0〜1` を唯一の情報源とする。`journeyProgress` は速度曲線を介して `s` へ写像してよいが、次の処理はすべて同じスプラインを弧長で評価する。

- カメラ位置と先読み注視点
- 地形テクスチャまたはシェーダーの `trail mask`
- 草原・林床マテリアルの混合位置
- 道端の根、草、シダ、苔岩、花、落ち葉の配置基準
- 橋の中心、向き、取り付き位置

各処理が独自の `sin` 式、別のBezier曲線、画像上の目測中心を持つことは禁止する。地面上の任意点は、スプライン上の最近傍点、その `s`、接線、左右法線、中心線からの符号付き距離 `d` を共通のルート評価関数から取得する。道マスクと道端配置はこの `d` を使う。

踏み跡の設計幅 `trailWidth(s)` は最低限、次の制御点を滑らかに補間する。区間境界で一次微分が急変しない `smoothstep`、Hermite補間、または同等の連続補間を用いる。

| `s` の目安 | 場所 | 設計幅 |
|---:|---|---:|
| 0.00 | 草原 | 2.4m（許容2.2〜2.5m） |
| 0.20 | 林縁手前 | 2.1m（許容1.8〜2.2m） |
| 0.55 | 森の入口 | 1.8m |
| 0.75 | 森内部 | 1.65m |
| 0.82〜0.94 | 橋手前の重点区間 | 1.5〜1.7m |
| 1.00 | 橋への取り付き | 1.6m前後 |

設計幅は明色の塗り幅ではなく、踏圧が視覚的に読めるおおよその幅である。エッジには低周波の揺らぎを加え、根や植生の侵入で局所的な有効幅を欠かす。ただし、短区間で0.3m以上跳ぶような急な幅変更や、橋直前だけ漏斗状に絞る形は禁止する。

`trail mask` は踏み跡全体を均一な明色で塗らない。中心部にも、林縁から徐々に次を戻す。

- 苔と暗い湿り色: 面積比の目安5〜12%
- 落ち葉と小枝: 面積比の目安8〜18%
- 短い草切れ: 面積比の目安3〜8%。橋への取り付きでは減らす

数値はグレーボックス後の画面確認で調整してよい。通行方向を連続した低周波の土色と踏圧で読み取れることを優先する。復帰要素はシード付きの決定的な分布とし、固定的な縦筋、等間隔、中央一列、左右対称を避ける。細かな斑点を全面へ均等散布して高周波ノイズにしない。

根、草、シダ、苔岩は中心線の左右法線を基準に道端へ配置し、一部を設計幅の内側へ不規則に侵入させる。侵入量、間隔、左右の出現順をシード付きで変え、同じ `s` で左右一対にしない。局所的に有効幅を狭めても、重点区間では連続して約1.2mを下回らず、カメラの先読み方向から橋の中央と対岸の明るい抜けを隠さない。

### 地形に追従するカメラ

カメラの基準高は次で決定する。

```ts
cameraY = terrainHeight(cameraX, cameraZ) + eyeHeight
lookAtY = terrainHeight(lookAtX, lookAtZ) + lookAtHeight
```

`eyeHeight` は約1.5mを基準とする。注視点は同じ中心線の弧長上で数m先を評価し、その地点の地形高を参照する。基準カメラ姿勢は `s` だけから決定し、フレーム履歴へ依存させない。

地形高を滑らかにする必要がある場合は、中心線上の現在位置の前後を固定距離でサンプリングする空間フィルタ、または事前生成した平滑な高さ関数を使う。同じ `s` から常に同じ高さが得られる方式を原則とする。時間ばねや前フレームからの補間を基準姿勢へ使わない。

歩行揺れなど時刻依存の動きは、決定的な基準姿勢の後に加える一時的な視覚オフセットとして分離し、スクラブ、スクリーンショット、数値テストでは無効化できるようにする。本番で時間平滑化を使う場合もこの一時的オフセットに限定し、基準姿勢、地形追従、`s` のスクラブ再現性へ影響させない。同じ `s` とシードからカメラの基準位置・高さ・注視点を毎回決定的に再現できなければならない。

## 5. 樹木と植生

- 森内部は、高木、亜高木・若木、低木、草本、林床の5層を画面上で判別できる密度にする。
- 成木3樹形、若木2樹形を基準に、左右対称、同じ高さ、等間隔の並木を避ける。
- 幹は根元、下部、上部を分節し、根元を太く、上へ先細りさせる。主枝は樹高の半分前後から分ける。
- 根は地形へ沿う放射状の短い形状として道端へ露出させる。
- 樹冠は個別の葉を作らず、枝先ごとに3〜6個の大きな水彩面または樹冠塊へまとめる。
- 遠景の樹冠面は近景より低彩度・低コントラストの専用テクスチャを使う。
- 草、シダ、低木は道際まで迫らせるが、進行方向と小橋を隠さない。
- 森内部で空が見える割合は約30〜45%を目安とする。
- 風揺れは高木、低木、草で周期と振幅を変える。

## 6. レンダリング要件

- WebGLベースの3Dレンダラーを使用する。
- 立体物は色面を保つ2〜3段階の柔らかなトゥーン陰影とする。
- 紙の粒子は画面全体へ薄く一度だけ適用し、各素材へ重複させない。
- 水彩のにじみは輪郭付近と色境界へ限定し、画面全体をぼかさない。
- 写実的PBR、写真樹皮、強い鏡面、強い黒アウトラインを使わない。
- 接地影と木漏れ日は、細密な葉影ではなく大きな柔らかい色面として整理する。
- 距離霧は現在地の空気色へ寄せ、遠景の彩度とコントラストを下げる。
- 光柱、光粒、発光は注視点の誘導に必要な場所だけへ少数配置する。

## 7. 本番入力と検証操作

レンダラーは次の入力だけで同じ状態を再現可能にする。

```ts
type JourneySceneInput = {
  journeyProgress: number // 0〜1。本番では文をまたいで単調増加
  isTyping: boolean
  typingPace: number      // 演出強度にだけ使用
  reducedMotion: boolean
}
```

- 入力された `journeyProgress` を単調な `routeMapping` で空間位置 `s` へ写像し、カメラの基準姿勢、地形高、土地の混ざり具合は `s` だけから決定する。
- 本番の `journeyProgress` はステージ全体の進捗であり、文が終わっても0へ戻さない。一文の `sentenceProgress` を代用しない。
- `isTyping` は足取り、風、粒子などの環境反応へ使う。入力停止時も旅座標とカメラ位置を戻さない。
- `typingPace` は歩行揺れ、風、粒子などの演出強度だけへ使い、カメラの移動距離や旅座標を直接変えない。
- `reducedMotion` では上下・左右の歩行揺れ、近景の強い視差、粒子を減らす。旅の到達位置と場面内容は変えない。

確認画面は、入力接続を試す `journeyProgress` スライダーとは別に、空間検査用の `s` 直接指定を持つ。`s` の直接指定は任意位置を往復して地形・植生・カメラを検査するための**デバッグ操作**であり、本番挙動ではない。6コマと橋手前の提出画像は `s` を直接指定して撮影する。10秒デモは `journeyProgress` を0から1まで一方向に進め、`routeMapping` を介して `s` を更新し、終端で停止する。本番も通常プレイ中に終端から始端へループしない。

## 8. 技術試作の現在地

`artwork/renderer-prototypes/watercolor-journey-renderer.html` で確認できるのは、主に次の技術要素である。

- Three.jsによるWebGL描画
- 一枚の地形、曲線状の道、簡略化した幹・根・樹冠面
- 水彩風に生成したテクスチャ、トゥーン材質、紙目、距離霧
- 草、岩、倒木、小川、簡易な橋、光柱、粒子
- 自動前進、一時停止、進捗および描画パラメータのスライダー

一方、現状は森内部中心であり、次の不足がある。

- 花の草原、林縁、成木通過を含む6コマの明確な構成になっていない。
- 草原と森をつなぐ土地別マテリアル・植生遷移がない。
- 遠い山、正本どおりの専用モデル、5層の森密度は完成していない。
- 自動再生は約10秒ではなく、終端で始端へループする。
- `isTyping`、`typingPace`、`reducedMotion` を受け取る本番用インターフェースではない。
- 一人称の腕・鞄はデバッグ表示であり、今回の完成要件に含めない。
- カメラの横位置、テクスチャ上の道中心、地形の起伏がそれぞれ異なる式で作られており、共通の中心線・弧長座標を唯一の情報源にしていない。
- 地形テクスチャの道幅が全区間でほぼ一定で、橋手前を1.5〜1.8mの獣道へ連続的に絞る設計になっていない。
- 道の中央が複数の明色ストロークで広く塗られ、苔、落ち葉、草切れを戻す密度制御や、根・植生による非対称な有効幅の欠けを実装していない。
- カメラのY座標が固定値を基準としており、`terrainHeight(cameraX, cameraZ) + eyeHeight` で地形へ追従していない。注視点も先読み位置の地形高を参照していない。

したがって、このHTMLを品質版へそのまま継ぎ足さない。使える描画実験は再利用候補として評価しつつ、次工程では正本の6コマに沿うグレーボックスを構成し直す。

## 9. 評価項目

- 0.00〜1.00で草原、林縁、成木通過、森内部、小川が同じ空間として連続して見えるか。
- 6コマの各位置で、正本の必須要素と景色の変化を判別できるか。
- 成木通過時に背景交換、クロスフェード、暗転がないか。
- 道が茶色い長方形や公園の舗装路に見えず、森へ進むほど獣道らしく細くなるか。
- 森内部で5層の植生が読め、近景の根、草、苔岩が道端を自然に欠いているか。
- 樹冠面が平板な看板にも、多面体の塊にも見えないか。
- 近景には十分な視差があり、中遠景は落ち着いて見えるか。
- スライダーを往復しても地形、植生、材質が急に切り替わらないか。
- 文を模した区切りを越えても旅座標が戻らないか。
- 紙目、光、粒子が中央上部・下部のタイピングUIの可読性を妨げないか。
- reduced motion時もルートと到達位置を理解できるか。

### 中心線と実効幅のデバッグ検査

6コマの一人称スクリーンショットに加え、空間位置を直接 `s = 0.82`、`0.90`、`0.96` に指定して次のデバッグ画像を提出する。時刻依存の歩行揺れや時間平滑化は無効にする。

1. 上方または斜め上方ビューに、共通中心線、設計幅の左右境界、カメラ位置、先読み注視点、橋中心を重ねる。
2. 道マスクの中心と共通中心線の横ずれをメートル単位またはワールド単位で表示する。
3. 中心線法線上の断面で、設計幅と根・植生侵入後の実効幅を表示する。
4. 地形面、基準カメラ高、実際のカメラ高を同時表示し、地形追従を確認する。

合格条件:

- 道マスク、カメラ経路、橋中心が同じ中心線上にあり、目視可能な恒常的な横ずれがない。数値検査では道マスク中心のずれを原則0とし、離散化誤差も設計幅の2%以内とする。
- `0.82〜1.00` の設計幅が1.5〜1.8mに収まり、隣接サンプル間に急な幅変化がない。
- 根・植生で輪郭が不規則に欠ける一方、実効幅は重点区間で連続して約1.2m以上あり、橋中心への視線が残る。
- 一人称ビューで地面の明色面が道路状に見えず、中央の苔・落ち葉・草切れが読めるが、進行方向を見失わない。
- 基準カメラ高が全検査点で、同じ `s` から決定される平滑な地形高と `eyeHeight` の和に一致する。同じ `s` へ別方向からスクラブしても基準姿勢が一致し、地形へ潜る・不自然に浮くフレームがない。

## 10. 承認ゲートと作業順序

1. 正本の10秒・6コマに対応するルート、地形、カメラ、主要配置をグレーボックスで作る。
2. 6コマ位置のスクリーンショットを提出し、基準画像と比較する。
3. ルート、カメラ、道幅、成木通過、森密度、小川への見通しに加え、橋手前の中心線一致、実効幅、地形追従カメラのデバッグ画像について承認を得る。
4. 承認後にだけ、専用モデル、土地別マテリアル、シェーダー、植生、光・風・水面を品質版へ進める。
5. 本番入力を模した単調増加の `journeyProgress` と文区切りで、位置が戻らないことを検証する。
6. 当該区間の完成後にのみ、次区間や全地域への展開を検討する。

技術試作の存在は手順1〜3を省略する理由にならない。グレーボックスの承認前に品質版の作り込み、全6地域向けの汎用化、ゲーム本体への組み込みを開始しない。
