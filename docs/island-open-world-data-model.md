# ことば島 オープンワールド環境データ設計

## 目的

全島模型と実際に歩くフィールドを別々の島として作らず、同じ地理データを距離と用途に応じたLODで描画する。現在の周遊デモは、この構造を検証する全島ビュー兼移動カメラである。

## 共通データ層

| 層 | 正本 | 用途 |
|---|---|---|
| 地形 | `islandTerrainSurface.ts` | 海岸線、標高、気候、流域、海岸帯 |
| 周遊route | `islandGrandTour.ts` | 景観確認用の閉路と見どころ |
| 水系 | `islandHydrology.ts` | 三支流、ことば川、南西の河口湾 |
| 自然環境 | `islandEnvironment.ts` | 木、低木、草、花、葦、玄武岩の決定論的配置 |

## 地表材質

気候区分を三色の帯として直接塗らない。湿度、標高、海岸からの距離を連続値として混ぜ、乾いた溶岩土、湿潤土、草地、露岩へ徐々に変化させる。海も深海・外礁・浅海の分類境界を色帯にせず、水深から連続的に色を求める。

海の遠景は島の下へ置く球面海を唯一の連続面とし、有限サイズの水面板を遠方まで見せない。浅瀬・礁・濡れ砂の色と透明感は海岸から約1.5km以内の局所水面で補い、沖へ向かって透明度を0まで連続的に落とす。球面海には微細な手続き波を与え、海岸近傍の層と重なっても矩形端や同心円状の切れ目が見えないことを全島俯瞰と追従視点の双方で確認する。

白砂浜は単一の黄色面にしない。内陸側から海浜植物、明るい乾砂、少し暗い濡れ砂、白い波打ち際、透明度の高い青緑の浅瀬の順で読み分ける。砂浜地点では通常の俯瞰カメラを少し下げ、浜の長さと海の水平線が同時に見える構図にする。全島地形の標高アンカーは変更せず、今後のgameplay-near LODで足元の微地形、砂粒、足跡、寄せ波を追加する。

周遊デモのポケット浜では、そのgameplay-near LODの先行検証として、正本標高を保持したまま海岸から約1.45kmだけを滑らかな棚状地形として描画する。砂上ではデバッグ用routeをほぼ非表示にし、二列の足跡、貝殻、流木、海浜草で歩行可能域を示す。寄せ波は立体tubeにせず、水面直上の細い三本線を位相違いで明滅させる。通常追従カメラも従来より低くし、地面を見下ろすのでなく進行方向と水平線を見上げられる初期角度にする。

routeは景観点を直線で結ばず、海岸段丘・谷底・広い尾根肩を通る閉じた曲線として設計する。急斜面を補正だけで無理に登らせず、自己交差と急な折返しを避ける。地表はroute中心の左右約280mを12%勾配目標で連続的にならし、外側約340mで元地形へ滑らかに戻す。カメラ、route mesh、現在地markerが参照する任意の進捗ごとにこの地表を再sampleし、一定の最小offsetだけを加える。これにより、制御点間の起伏でもrouteが浮いたり地面へ潜ったりしない。現在の全周数値QAでは地表誤差`1.01e-16`、最大局所勾配約17.3%である。

樹木・岩・倒木は樹冠を縮めて道を空けない。幹または本体が中心線へ近過ぎる個体だけを、元の群落側へ最小限平行移動する。樹冠寸法と森の連続性は維持する。

全島LODでは固定シードの低周波色むらと細粒を一枚の手続きtextureとして重ねる。regional/gameplay LODでは同じworld座標を入力にし、腐植、苔、落葉、砂礫、濡れ面などのmaterial layerを追加する。カメラ移動やセル再ロードで模様の位置を変えない。

## セルとLOD

自然環境は安定したIDを持つ約650m四方のセルに分割する。同じセルを再ロードしても種類・位置・回転・尺度は変わらない。

- `globe`: 樹林や湿地を色面と少数の代表形状で表示する。
- `regional-corridor`: 現在地周辺と進行方向のセルを読み込み、群落の密度と主要樹形を表示する。
- `gameplay-near`: 道の周囲を個体モデル、地表植生、倒木、当たり判定、発見演出へ置換する。

LODは同じinstance IDを段階的に詳しくする。近景ロード時に別座標へ木を生やしたり、遠景の山・川・湾を交換したりしない。

## 現在の実装範囲

- 全島のセルと環境instanceを決定論的に生成する。
- 気候・標高・海岸帯から7種類の自然要素を選ぶ。
- 北東の湿潤側は高密度林、南西の雨陰は草・花・岩、河口は葦を優先する。
- ルート中心から一定幅を空け、歩行路を樹木で塞がない。
- 植生を広い帯状に削除せず、樹木・岩・倒木の近接個体だけを群落側へ移す。routeは地形と景観順を優先した正本曲線を維持する。
- Three.jsでは同種をInstancedMeshでまとめる。
- 南西の沈水湾へ流れ込む三支流と本流を全島座標上に表示する。川は円筒や直線tubeではなく、地表追従する蛇行水面、幅広い濡れた岸、大小を崩した河原石で構成する。
- 花は浮遊する多面体にせず、細い茎と小さな花冠を一体で表示する。デバッグ用landmark pinは景観表示から除外する。
- 南東は背の低い草と花が風に開ける草原、南岸は玄武岩島の上へ隆起した旧礁由来の淡色石灰岩柱群として、森とは異なる輪郭と色を持たせる。
- ポケット浜付近は再生速度を通常の38%へ落とし、白砂・浅瀬・足跡を読める時間を確保する。
- 全島試作では2048px shadow mapによるリアルタイム影を使う。静的ベイクは景観と太陽方向が固まるまで行わない。

## 森でのカメラ視認性

森を広い直線帯で伐採して視界を作らない。追従カメラは通常より少し高く・近い俯瞰寄りに置く。カメラと直近の操作地点を本当に遮る少数の木だけを幹と樹冠の組で一時的に描画対象から外し、樹形の大きさや配置、左右の樹林、遠方の樹冠は変えない。全島俯瞰では全ての木を描画する。樹冠だけの縮小・半透明化は不自然なため採用しない。

正式なキャラクター統合後は、遮蔽判定にヒステリシスを設けて表示のちらつきを防ぎ、カメラ衝突時はcamera boomも短くする。森全体の密度や配置データ自体は変更しない。

## 次の制作ゲート

1. 全島俯瞰で森・雨陰・湿地・川・湾の大配置を承認する。
2. 草原→東林の1セルをgameplay-near品質へ作り、遠景instanceとの位置一致を確認する。
3. 移動に応じたcurrent/forward cellのload・behind cellのunloadを実装する。
4. 衝突、枝道、採集可能物、動物の遮蔽をnearセルだけへ追加する。
5. Stage 1→2境界でterrain、水系、植生セル、BGMが再ロードなしに継続することを確認する。
