# 36ステージ一本道化 正本仕様

## 1. 決定事項

従来の「6学年 × 6ステージ」を、学年選択のない一本の物語（全36ステージ）へ変更する。旧学年は学習難度ではなく、物語を整理する6つの「章」としてだけ残す。プレイヤーの登録学年は進行条件から切り離し、問題抽選の優先属性としてだけ使う。漢字には常にルビを付ける。

進捗保存は schema v3 でリセットしてよい。旧形式と新形式を恒久的に二重管理しない。

### 1.1 天空到達の再設計

本格的な雲上世界への到達は最終章（Stage 31〜36）だけにする。旧学年構成に由来する6回の `古代樹→雲上→草原` 周回は廃止し、Stage 1〜30は地上・山地・海岸・地下水路・古代樹内部を通って天空への理由と道を段階的に見つける。詳細と移行対象は [一本道物語再構成案](linear-story-sky-final-chapter-restructure.md) を正とする。

## 2. 階層と用語

- 物語：ステージ1から36まで一本道で進む全編。
- 章：6ステージごとの物語上のまとまり。旧学年ストーリーを再利用するが、UIで「○年生」とは呼ばない。
- ステージ：物語上の一話。クリアすると次の通し番号を解放する。
- コース：一つのステージ内にある練習区間。短文を複数配置し、同じ場所と事件を進みながら練習量を確保する。
- 問題：一回のタイピング対象。

## 3. 旧IDから新番号への対応

変換式は `newStage = (oldGrade - 1) * 6 + oldStage` とする。

| 新ステージ | 旧ID | 章 | 既存タイトル |
|---:|:---:|---|---|
| 1–6 | 1-1〜1-6 | 第1章 | ひかりの種と はじめての地図 |
| 7–12 | 2-1〜2-6 | 第2章 | 風のコンパスと 眠った風車 |
| 13–18 | 3-1〜3-6 | 第3章 | 消えた星座と 夜空の地図 |
| 19–24 | 4-1〜4-6 | 第4章 | にじ色の潮と 珊瑚の鐘 |
| 25–30 | 5-1〜5-6 | 第5章 | 古代樹の図書館と 月の鍵 |
| 31–36 | 6-1〜6-6 | 最終章 | ことば島の約束と 天空の王冠 |

完全な一対一対応は `src/game/linearStageConfig.ts` を正とする。問題・報酬・図鑑の旧 `grade-course` 参照は移行中だけ `legacyId` から解決し、最終的には `stage-N` へ置換する。

## 4. 一本の物語への接続

既存36話のタイトル・導入・達成文・友達・宝物は原則維持する。各章の6話目が大団円になり、次章1話目で別事件が突然始まることだけが不自然なため、以下の章間ブリッジを追加する。

| 境界 | 章末に加える予兆 | 次章冒頭に加える理由 |
|---|---|---|
| 6→7 | 花が戻った直後、風だけが静まり風車が止まる | 花の種を島へ運ぶため、止まった風を取り戻す |
| 12→13 | 風が戻るが、夜の航路を示す星だけが見えない | 船を安全に導くため、消えた星座を探す |
| 18→19 | 新しい星座が海を照らし、色を失う入り江が見える | 星明かりを頼りに、珊瑚の鐘の異変へ向かう |
| 24→25 | 虹の中に古い文字が現れ、島の記録が消え始める | 虹が示した古代樹の図書館へ記録を戻しに行く |
| 30→31 | 戻った記録が、天空の王冠の亀裂を警告する | 旅で得た仲間と六つの力を結び、最後の異変へ挑む |

実装時は章末 `completion` の後に `nextChapterTeaser`、章頭 `intro` の前に `chapterBridge` を表示する。既存文を無理に書き換えず、接続文を独立フィールドにする。

## 5. 難易度設計

難度は漢字や学校学年では決めない。主指標は次の6つとする。

1. 読みの文字数（かな換算）
2. 文節数と文の数
3. ローマ字入力の総打鍵数
4. 拗音・促音・撥音・長音の組み合わせ
5. 句読点・数字・記号の有無
6. 同じ指の連続、左右交互、上段・下段など運指の複雑さ

| ステージ | 難度帯 | 目安 |
|---:|---|---|
| 1–6 | はじめの一歩 | かな5–12字、1–2文節、清音中心。1ステージ内で急に長くしない |
| 7–12 | 短いことば | かな8–18字、2–3文節。濁音・半濁音・撥音を段階導入 |
| 13–18 | 文をつなぐ | かな12–24字、2–4文節。拗音・促音を組み合わせる |
| 19–24 | 表現をひろげる | かな16–30字。長音と読点を導入し、短文を二つつなぐ |
| 25–30 | 複雑な文 | かな20–38字。句読点、数字、かぎ括弧を一種類ずつ導入 |
| 31–36 | 物語を打つ | かな24–45字。複文と複数要素。ただし一問45字を上限目安とする |

漢字は語彙表現として全ステージで使用できるが、表示は常に `ruby` を正としてルビを付ける。漢字の習得学年を解放条件や難度点に使わない。記号入力を含む問題では、JIS/US配列差があるキーの事前案内と判定テストを必須にする。

各ステージは最低3コースを基本とし、各コース3–5問とする。序盤ほど短い問題を多く置き、「短い問題を十分練習する前に長文化する」ことを避ける。コース1は新要素なし、コース2で新要素を一つ導入、コース3で復習を交えて定着させる。

## 6. 解放と画面動線

- 初回は基礎練習とステージ1を表示する。
- ステージNの最終コースをクリアすると `stage-N` を完了記録へ追加し、N+1を解放する。
- クリアダイアログの主ボタンは「次のステージへ」。Spaceでも同じ動作をし、画面にガイダンスを表示する。
- ステージ一覧は36枚を平坦に並べず、章ごとの地図または連続した旅程として表示する。カードクリックで即開始する。
- 「学年を選ぶ」「○年生のステージ」は削除する。登録学年は必要なら保護者向け分析属性としてだけ残し、ゲーム進行には使わない。
- 問題一覧・図鑑・ランキングの場所表示も「第Nステージ」へ変更する。

## 7. 保存 schema v3

`ProfileData.schemaVersion` を3へ上げ、次の形へ一本化する。

- `completedStageIds: string[]`：`stage-1` 形式。
- `stageBest` / `stagePlays`：キーは `stage-N`。
- `lastStage: number`：最後に選択した1–36。プロフィールの `lastGrade` は進行判定に使わない。
- `typingDisplayCase: 'lower' | 'upper'`：ローマ字表示の大文字・小文字。プロフィール単位で保存し、移行時の既定値は `lower`。
- 問題別統計、キー統計、図鑑、日次活動、目標、音設定は維持する。
- v2以前からの移行時は `completedCourses` と旧スコアをリセットする。ユーザーが許容済みのため、曖昧な推測移行はしない。
- 保存完了後は旧フィールドを書き戻さない。

## 8. 実装順序

1. `LinearStage` と36話変換層を導入する。
2. ストーリー接続文と難度メタデータを追加し、データ検証テストを作る。
3. schema v3へ移行し、完了ID・直前ステージを通し番号化する。
4. Appの選択状態と解放判定を `grade + course` から `stageNumber` へ変更する。
5. タイトル、ステージ一覧、学習記録、図鑑、クリア遷移から学年依存を除く。
6. 問題JSONを新ステージIDへ変換し、各ステージを複数コース化する。
7. 難度監査に従って問題を段階的に追加する。

大量の問題文変更とUI変更は同時に行わない。まず通し番号で既存問題を最後まで遊べる状態を作り、その後に問題数と難度曲線を拡充する。

## 9. 受入基準

- 学年を選ばず、基礎練習から36話を順番に解放できる。
- ステージ6→7、12→13、18→19、24→25、30→31で物語の因果が読める。
- 旧36話のタイトル、主要目的、友達、宝物が欠落しない。
- 一つのステージの途中ではクリア扱いにならず、最終コース完了時だけ次へ進む。
- 漢字を含む全問題でルビが表示され、漢字そのものを入力させない。
- 長さ・文節・ローマ字要素が原則として難度帯の上限を超えない。
- 句読点・数字・記号は後半で一要素ずつ導入され、配列差で理不尽な誤判定を起こさない。
- schema v2以前のデータを開いてもクラッシュせず、許容された進捗リセット後に保存できる。
- 既存の問題統計、キー統計、図鑑、音設定は移行後も残る。
- 全テスト、lint、production buildが成功する。

## 10. 推奨学年による問題選定

### 10.1 問題metadata

各問題へ次のmetadataを持たせる。`recommendedGrades` は解禁条件ではなく、その語彙・内容を優先して届けたい学年の配列である。複数学年に適する問題を重複登録しないため配列とする。

```ts
type QuestionSelectionMetadata = {
  recommendedGrade: Grade
  difficultyLevel: number
}
```

`recommendedGrade` は旧データの学年を初期値にできるが、監査時に語彙・内容から見直す。`difficultyLevel` は問題監査で算出・確定する共通尺度であり、漢字の習得学年を含めない。文字数、文節数、打鍵数、拗音・促音・撥音・長音、句読点・数字・記号、運指の複雑さから決める。各ステージまたはコースは `difficultyCeiling` を持つ。

### 10.2 選定順序と割合

1. まず `difficultyLevel <= difficultyCeiling` を満たす候補だけに絞る。この上限は学年による優先より常に強い。
2. 同じ問題IDを除き、プロフィール学年と `recommendedGrade` が一致する問題を優先抽選する。
3. 1コースの目標は該当学年70%、他学年30%とする。10問なら7問を優先枠、3問を混在枠とする。
4. 70%は目標であり保証ではない。優先候補が不足したら上限内の他学年候補で埋め、他学年候補が不足した場合は優先候補を追加する。
5. 全候補数が必要数未満なら重複出題して水増しせず、存在する問題だけを返す。UIは問題数が少ないコースとして正常に完走できる。

混在枠により語彙の変化と問題不足への耐性を持たせる。難度上限を超える問題を、問題数合わせのために混ぜてはならない。

### 10.3 固定期間とseed

- 問題セットと順番はコース開始時に一度だけ確定し、run stateへ保存する。
- seedは `profileId + stageId + courseId + visitId` から作る。純関数へ同じ候補・条件・seedを渡せば同じ結果になる。
- ミス後の同run再挑戦、画面内の再開、問題間のadaptive更新では同じ `visitId` を使い、再抽選・再ソートしない。
- コースを完了または明示的に退出し、通常再訪を開始するときは新しい `visitId` を発行して再抽選する。
- 弱点練習は通常コース抽選とは別モード・別seedとし、弱点優先ロジックを混ぜない。

`Date.now()` や実行途中の成績を純関数内部から参照しない。時刻や訪問回数を使う場合は呼び出し側が `visitId` として渡す。

### 10.4 重複とfallback

- 同じIDの候補が複数由来で渡されても最初の一件だけを使う。
- 優先枠と混在枠の間でも同一IDを再利用しない。
- 該当学年metadataが一件もなくても、難度上限内の候補から選べる。
- `recommendedGrade` が未設定の移行途中データは全学年向けではなく、非優先候補として扱う。
- 難度metadataが未設定の問題は、監査完了まで通常コース抽選へ入れない。暗黙に最低難度扱いしない。

選定実装の正本は `src/game/selectCourseQuestions.ts` の純関数とする。候補の絞り込み、割合、不足時fallback、seed再現性、重複防止を単体テストする。
