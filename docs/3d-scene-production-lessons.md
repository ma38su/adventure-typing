# 連続3Dシーン制作で得た共通ルール

最終更新: 2026-08-10
検証区間: `花と草原 → 木漏れ日の森 → 森内部の小川`
検証実装: `artwork/renderer-prototypes/meadow-to-forest-threejs-v1.html`

## 1. この文書の役割

草原から森の試作で判明した、次区間以降にも適用する空間設計、レンダリング、カメラ、制作手順の共通ルールを記録する。土地固有の構図や物語は各区間の制作ブリーフを正とし、本書はそれを実装可能な3Dシーンへ落とす際の補助基準とする。

次の `木漏れ日の森 → 星見の山道` を作る前に、対象区間のブリーフと本書を読むこと。

## 2. 絵コンテの扱い

- 完成イラスト調の絵コンテは、色、空気感、物語上の移動方向を示す雰囲気資料として使う。
- 3D実装基準には、再利用するモデル数、配置密度、遠景カード、光、霧を簡略化した実装用絵コンテを別途用意する。
- 草原から森では `artwork/preproduction/meadow-to-forest-storyboard-webgl-implementation-v2.png` を実装密度の基準とした。
- 一つのモデルを増やす前に、カメラ、ルートの曲がり、前景遮蔽、光、霧、配置差で場面変化を作れるか確認する。
- 連続する3コマを同じ中央直線路と左右の木列にしない。各地点へ「入口」「狭窄」「開け」「水辺」など異なる空間上の役割を与える。

## 3. 歩行ルートより広く世界を作る

最重要の反省点は、ルート沿いの見える範囲だけへ物を置くと、森ではなく「木を並べた通路」に見えることである。

- 地形と環境配置は、歩行ルートおよび通常カメラの視錐台より十分に広く作る。
- 森は道からの距離だけで作らず、ワールド座標上で横方向・奥行き方向へ面積を持つ土地として配置する。
- 林縁は本数だけでなく、木が生えている範囲の横幅で森らしさを判断する。
- 近景、中景、遠景、シーン外周の最低4層を持ち、道が曲がっても空の地面が露出しないようにする。
- 遠景・外周樹木は `InstancedMesh` 等でまとめ、描画負荷を抑えながらシーン境界を隠す。
- 通行帯は共通ルート、道幅、木の幹半径、余白から算出し、密度を上げても幹を道中央へ入れない。
- 区間終端でも環境を打ち切らない。橋、小川、門などの見せ場の両側と向こう側に、同じ土地が続く余白を作る。

草原から森の試作では、地形幅を44mから76mへ広げ、ルート外側へ最大約29mの樹林層を追加して初めて、カメラから土地の面積を感じられるようになった。この数値は次区間の固定値ではないが、ルートだけでなく視錐台外まで作る考え方を引き継ぐ。

## 4. 森の密度は本数だけで判断しない

- 森らしさは、樹木本数、占有範囲、幹の重なり、樹冠の連続、林床の層、遠景の遮蔽を合わせて判定する。
- 木を左右二列に増やすだけでは、密な並木道にしかならない。
- 樹冠は頭上で部分的につながり、幹は近景から霧の奥まで重なるようにする。
- 道際の低木だけで画面を埋めない。高木、若木、低木、草本、林床を異なる距離へ分散する。
- 森内部の空の抜けは必要だが、明るい草原と同じ背景色が大面積で見え続けないようにする。

## 5. 空、霧、光を土地に合わせて連動させる

背景色を固定すると、森へ入っても草原の空が木の隙間からそのまま見え、土地が変わった印象が弱い。

- 空はシェーダーまたは同等の仕組みで、現在地の土地色へ連続変化させる。
- 空色だけを変えず、距離霧の色と濃度、環境光、主光源、露出を同じ土地ブレンド値で調整する。
- 草原は淡い青空と暖かい地平線、森は青緑の空気色と低いコントラストを基準とする。
- 土地境界で背景交換やクロスフェードを使わず、旅座標から滑らかなブレンド値を求める。
- 水辺や出口の明るい抜けでは森のブレンドを少し戻してよいが、環境を突然別の土地へ変えない。
- 次の土地は正史の地理に合わせる。森の次は星見の山道なので、橋先の狭い抜けから遠い山稜を見せ、海は見せない。

## 6. 橋、小川、障害物

- 草原から森の橋は「森を抜けた後の橋」ではなく、森内部の小川に架かる橋である。
- 橋の両岸、対岸、左右外側にも森を続ける。橋だけを空の地面や矩形水面へ置かない。
- 小川は長方形平面ではなく、中心と岸幅が揺らぐリボン形状を使う。
- 水面、岸、橋、対岸路は共通ルートと地形高へ合わせる。
- 倒木などを道へ置く場合、配置するだけでは意図が伝わらない。ゲーム歩行確認では、接近時の視線、軽い減速、踏み越え、着地を一続きで検証する。
- `reducedMotion` では踏み越えの上下量と視線変化を減らすが、障害物を通過した事実と到達位置は変えない。

## 7. 確認再生とゲーム歩行再生

用途の異なる二つの再生を混同しない。

### 確認再生

- ルート、構図、土地遷移を一定速度で検査する。
- 歩行揺れを抑え、指定した旅座標の再現性を優先する。
- 6コマの比較画像やデバッグ画像はこちらで撮影する。

### ゲーム歩行再生

- 上下の足取り、左右の重心移動、わずかなロール、障害物反応を確認する。
- `typingPace` は足取りの周期、揺れ、風、粒子など演出だけへ使う。
- `typingPace` で旅座標や前進距離を変えない。ゲーム中の到達位置は `journeyProgress` だけで決める。
- 自動デモでは同じ進捗列を再生し、カメラ演出の差だけ比較できるようにする。

## 8. 物語と環境制作の境界

- ストーリースクリプトへ接続する前は、背景、植生、地形、橋、倒木、岩、道標など環境と小物を中心に作る。
- 未接続の台詞、動物、足あと、報酬、伏線記号を3D側へ先回りして入れない。
- 古代樹の渦巻き模様などは、形が読める専用テクスチャまたは承認済みモデルとして作る。欠けたトーラス等の仮形状を物語記号として残さない。
- 物語固有演出は、実際のステージ設定とイベント進行を入力として受け取れる段階で追加する。

## 9. 次区間「森 → 山」への適用

次区間を始める前に専用ブリーフを作り、少なくとも次を決める。

1. 森のどの地点から出発し、山道のどの標高・時間帯へ到着するか。
2. 森から見える山の大きさと、山側から振り返った森の占有範囲。
3. ルート外側へ確保する地形幅と環境チャンクの余白。
4. 森の青緑から山の灰青・夕金へ変化する空、霧、光、露出の制御点。
5. 林床、低木、高木が減り、草地、岩、低木、高原植生へ置き換わる距離差。
6. 次の入り江を見せる時点。山へ入った直後から海を大きく見せず、物語上の見通し地点で初めて提示する。
7. 確認再生とゲーム歩行再生の両方で判定する地点。
