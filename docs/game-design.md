# ことば島の大ぼうけん ゲームデザイン

最終更新: 2026-08-09  
対象: タイピング体験、ステージ進行、物語演出、UI、難易度、素材制作仕様

## 1. このドキュメントの目的

この文書は、[ストーリーバイブル](story-bible.md) に定めた物語を、タイピングゲームとしてどう体験させるかを扱う。世界の正史、登場人物の動機、各話で実際に起きる事件はストーリーバイブルを正とする。

## 2. 変えないゲームの骨格

本作の主操作は、提示された言葉をキーボードでタイピングすることである。

- 移動、探索、試練、収集、会話はタイピングの結果として進む。
- 反射神経を要求するアクション、戦闘コマンド、複雑な移動操作、連打を必須にしない。
- 新しい仕掛けはタイピングを置き換えず、「何のために入力しているか」を豊かにする。
- 正確に入力を続ければ物語は必ず進む。速度は追加評価や演出の強さへ使い、物語停止の主因にしない。
- ミスを罰の演出にせず、修正と再挑戦を学習体験として扱う。

## 3. 設計レイヤー

| レイヤー | 決めること | 正となる文書 |
|---|---|---|
| ストーリー | 誰が、なぜ、何と向き合い、何を変えるか | `story-bible.md` |
| ステージ・演出 | 背景、音、動き、カメラ、台詞でどう見せるか | 本書 |
| ゲームシステム | 問題、入力判定、進行条件、得点、難易度 | 本書と実装仕様 |

良いタイピング体験から物語を調整することはできる。ただし、変更するときはストーリーバイブルを先に更新し、物語上の出来事とゲーム上の実現方法を混同しない。

### 用語の階層

| 用語 | 定義 | 例 |
|---|---|---|
| ステージ | 冒険する大きな場所、または大きな学習テーマ | 花と草原、タイピング基礎 |
| ルート | ステージ内で選択する挑戦経路 | ホームポジション、人差し指、数字 |
| 問題 | プレイヤーが実際に入力する最小のタイピング課題 | 「ふ」を`fu`で入力する、文章を一文入力する |

画面上ではこの三語を役割に応じて使い分ける。タイピング基礎ステージは複数ルートを持つ。本編ステージは現状、ステージから複数問題へ直接進むため、選択する意味のないルート階層を設けない。

## 4. 基本プレイループ

1. 起動時にユーザーを選択する。未登録の場合は専用画面で名前、学年、キャラクターを設定する。
2. 選択したユーザーの設定、進捗、学習履歴、図鑑を読み込む。
3. ステージ選択画面で、挑戦可能またはクリア済みのステージを選ぶ。
4. 選択したステージの目的を知る。
5. タイピング問題を進めながら、主人公が左から右へ旅をする。
6. 正解によって土地の手がかりや変化が段階的に現れる。
7. ステージ終盤で、その話のクライマックス試練に入る。
8. タイピングを通して試練を解決し、土地が回復する。
9. 案内役との結びつきやキーアイテムを得る。
10. 次の話へ続く道や予告を見せる。

本編ステージは1から順番に解放する。クリア済みステージは再挑戦できる。プレイ中はいつでも終了でき、オートセーブ後にユーザー選択画面へ戻る。

## 5. ローマ字ステージのチュートリアル設計

### 役割

ローマ字ステージは本編開始前のプロローグであると同時に、いつでも戻れる基礎練習場所である。物語設定はストーリーバイブルの「ことばを運ぶ はじまりの灯台」を正とする。

チュートリアルの目的は、すべてのローマ字を最初に暗記させることではない。プレイヤーが次を理解し、自力で本編の入力を始められる状態を作ることである。

- 画面に示されたかなと対応するキーを入力する。
- 正しい入力によって、文字と物語の状況が変化する。
- 間違えても修正して続けられる。
- 分からない文字は表示を見ながら入力してよい。

### 学習段階

タイピング基礎は、五十音順の暗記ではなく、タッチタイピングの身体的な習得順に構成する。画面上では一つの「タイピング基礎ステージ」として入口をまとめ、その中に複数のルートを置く。

| ルート | 学習目標 | 必須／任意 |
|---|---|---|
| ホームポジション | F・Jの突起を目印に指を置き、打鍵後に戻す | 本編解放に必要 |
| 人差し指のキー | 左右の人差し指が担当する上下段のキーをまとめて覚える | 任意 |
| 中指・薬指・小指 | 手全体をずらさず、担当指だけを伸ばす | 任意 |
| 母音 | A・I・U・E・Oの位置と担当指を覚える | 任意 |
| 左右交互入力 | 次に使う手を準備し、一定のリズムで入力する | 任意 |
| ことばの実践 | 正しい指使いを保ったまま実用語を入力する | 任意 |
| 数字キー | ホームポジションから上段へ指を伸ばす | オプション |
| 記号キー | カンマ、ピリオド、ハイフン、スラッシュを担当指で押す | オプション |

各問題では、次に押すキー、左右どちらの手か、担当指、色分けしたキーボード、ホームポジションの目印を同時に示す。速さよりも正しい指、手元を見ないこと、打鍵後にホームポジションへ戻ることを優先する。

### 本編解放と継続練習

- 「ホームポジション」を完了した時点で、選択中の学年の本編ステージ1を解放する。
- 残りの基礎練習と数字・記号は本編開始の必須条件にしない。
- 未完了の練習は、タイトル画面からいつでも再開できる。
- 本編で苦手な入力が見つかった場合、対応する場所へ戻る導線を出せるようにする。
- 再練習を「やり直し」ではなく、「灯台の光を整える仕事」として肯定的に表現する。

### プロローグのクライマックス

ホームポジションルートの完了後に、短い「灯台点灯」の場面を設ける。これは本編へ進むための最初のクライマックスだが、残りのルートが未完了でも成立する小さな点灯とする。

基礎練習を進めるほど灯台が明るくなる追加演出を設けられる。これにより、早く本編へ進みたいプレイヤーを止めず、継続練習にも達成感を用意する。数字・記号は追加技能として扱い、物語進行条件へ含めない。

演出案:

1. トワが灯台上空から位置を知らせる。
2. 練習で集めた光が、入力に合わせて灯台の輪へ収まる。
3. 灯台が点灯し、海霧に航路が現れる。
4. 読めなかった手紙の一部が読めるようになる。
5. 白うさぎの足あとと、花と草原への出発ボタンを示す。

### チュートリアル固有の原則

- 制限時間を設けない。
- 速度評価を前面に出さず、入力できたことを主に評価する。
- 初回はローマ字表記と押すキーを明瞭に示す。
- 誤入力で灯台やトワが壊れる、落ちる、悲しむ演出をしない。
- 説明文を長くせず、一つ説明したらすぐ一文字入力して確かめる。
- キーボード配列の違いがあっても、文字入力の学習を妨げない設計にする。

## 6. クライマックス試練のゲーム化方針

ストーリーバイブルの各話に定めた試練を、通常問題の延長にある特別なタイピング場面として表現する。名称候補は「ことばの大試練」「クライマックスチャレンジ」とし、作品内で「ボス戦」という戦闘語を前面に出さない。

### 共通構造

1. **予兆**: 背景、音、案内役の反応で異変を知らせる。
2. **目的提示**: 「風見台を直そう」など、入力の意味を短く示す。
3. **段階進行**: 3〜5段階を目安に、正解ごとに状況が改善する。
4. **最後の一文**: その話の主題を象徴する入力で解決する。
5. **解放**: 一度静かになった後、土地の回復を大きく見せる。
6. **余韻**: キーアイテムと次話への接続を示す。

具体的な問題数、制限時間、速度条件は一律に固定せず、対象学年と入力負荷を検証して決める。

### 緊張感の作り方

- 波、霧、風、暗さなどが段階的に変化する。
- 音楽のテンポや音数を少しずつ増やす。
- 問題の残りではなく、装置の復旧や仲間の作業として進捗を見せる。
- 終盤で過去に得たアイテムや仲間を再登場させる。
- 失敗時は状況が一段階弱まる程度とし、ゲームオーバーを基本にしない。
- 恐怖、落下、溺れ、追跡を過度に強調しない。

### ステージごとの演出原型

| ステージ | 演出原型 | 入力で起きる変化 |
|---|---|---|
| 花と草原 | 閉じた道、眠った花、散らばった手がかり | 花が開き、足あとや道が現れる |
| 木漏れ日の森 | 迷い霧、重なった音、分岐した合図 | 霧が晴れ、音や道が一つにつながる |
| 星見の山道 | 強風、星見台、複数の進路 | 足場が安定し、観測器と星が点灯する |
| 珊瑚の入り江 | 大波、潮の渦、壊れた鐘や航路 | 波が弱まり、部品や航路が結び直される |
| 月影の古代樹林 | 閉じた書庫、白紙、古い問い | 文字と記録が戻り、根の門が開く |
| 雲上の遺跡 | 六つの台座、分かれた力、最終装置 | 過去五話の光が集まり、島全体が回復する |

## 7. 通常ステージの物語演出

### ステージ開始

前話で得たアイテムの働きで次の道を開く。徒歩、橋、船、根の門、光の階段など地理に沿って接続し、毎話を無関係なワープで始めない。

### 問題進行

- 正解: 主人公が進み、道沿いの灯りや土地の装置が一段階動く。
- 連続正解: 案内役が少し先で手がかりを見つける。
- ミス: 短い揺れや光の減衰。主人公や動物を責めない。
- 問題終盤: 次の土地を示す遠景、音、渡り便を見せる。

### 3D空間での発見と報酬表現

通常アイテムは、種類ごとの個別3Dモデルを原則として作らない。移動中のフィールドではアイテムそのものを陳列せず、「この場所に何かありそう」と気づける抽象的な予兆を環境へ置く。プレイヤーがタイピングに成功した後、短い取得演出を経て、2Dアイテムイラストを画面上へ大きく表示する。

基本の流れ:

1. 移動中に、発見物の種類に合った環境の予兆が見える。
2. 予兆へ近づくか問題の開始条件を満たすと、タイピング対象を提示する。
3. 成功すると、予兆が集まる、ほどける、立ち上がるなどの短い取得演出を行う。
4. 取得した2Dアイテムイラストを、名称や短い説明とともに大きく表示する。
5. 取得後は予兆を消すだけでなく、花が咲く、模様が静まる、光が道へ流れるなど、可能なら環境側にも結果を残す。

予兆はすべてを同じ光で表さず、発見物の性質を入力前に推測できるよう種類ごとに変える。

| 発見物 | フィールド上の予兆 |
|---|---|
| 種、小さな宝物 | 地面の柔らかな光、少数の粒、近くの草の小さな反応 |
| 動物 | 草や枝の揺れ、足跡、鳴き声、奥の一時的なシルエット |
| 古代の手がかり | 岩、木、地面に浮かぶ淡い模様や、低い共鳴光 |
| 水辺の発見物 | 反射、波紋、水面下の青緑の光 |
| 物語上の重要品 | その品に固有の環境変化と、必要に応じた簡略3Dシルエット |

予兆は柔らかな光、少数の粒、揺れる草、足跡、波紋、淡い模様などを組み合わせる。常時派手に発光させず、タイピングUIや進行方向の読解を妨げない。音による予兆には、揺れ、足跡、波紋など視覚上の手がかりも併用する。

次のいずれかに該当する場合だけ、簡略化した3Dモデルを個別に検討する。

- 道しるべ、橋、扉など、ルートや通行状態へ影響する物
- 取得前から形を見せる必要がある、物語上重要な品
- 取得後もフィールドへ残り、環境変化を示す物
- 複数の場面で反復し、3D空間内で共通の意味を持つ物

例外に該当しても自動的に3D化せず、抽象的な予兆と2D表示だけでは物語または操作が伝わらないかを先に確認する。3D化する場合も、写実的な小物を増やすのではなく、画風と視認距離に合う簡略形状にする。

制作順序は移動空間の承認と分離する。現在の「花の草原から木漏れ日の森へ」の移動グレーボックスには、発見物、取得演出、2D報酬表示を含めない。ルート、カメラ、道幅、植生密度、小川までの連続移動が承認された後、次段階で「地面の光を発見 → タイピング成功 → 2D報酬表示」を一種類だけ実装して検証する。その予兆の気づきやすさ、入力との因果、2D表示の見やすさ、取得後の環境変化を承認してから、他の発見物へ展開する。

### ステージクリア

報酬画面より先に、土地がどう変わったかを見せる。その後、案内役からキーアイテムを受け取り、次の目的地を示す。第6話では第1〜5話の小物と仲間を再登場させる。

## 8. 背景素材の制作仕様

### 必須構図

- 横長で、キャラクターが左から右へ徒歩移動する前提。
- 歩行レーンは画面下部のおよそ20〜35%に置き、全幅で連続させる。
- 道を消失点へ向けて急激に細くせず、横方向の連続性を優先する。
- 左右それぞれ10%はキャラクターとUIの安全領域とし、大きな花、岩、動物、文字を置かない。
- 主役級ランドマークは中央から少し奥へ置き、主人公の足元と重ねない。
- 画像そのものに人物、文章、ロゴ、進捗UIを含めない。

### レイヤー想定

1. 空・遠景: 時間、天候、次の目的地。
2. 中景: 土地を識別する建物、木、水辺、遺跡。
3. 歩行レーン: 明瞭で平坦な道とキャラクターの接地面。
4. 前景: 低い草、花、砂、小石。左右端と足元は控えめ。
5. 演出差分: 光、風、霧、星、花びら。可能なら背景本体と分離する。

### 学年・状態差分

六つのマスター背景を基礎に、以下を差分として作る。

- 時間帯と空模様
- 学年の主題色
- 異変発生中、試練中、解決後
- キーアイテムに関係する小物
- 前話から続く痕跡と次話を予告する遠景
- 案内役の巣、足あと、道具、郵便印

### 画像生成プロンプトの基本形

```text
子ども向けファンタジータイピングゲームの横長背景。
舞台は［ステージの土地］、表現する出来事は［学年・話の事件または試練］。
画面下部に、キャラクターが左から右へ歩ける幅広く連続した［土／木／石］の道。
道は遠近方向へ曲がらず、左右方向にほぼ水平。左右端はキャラクター用に静かで空ける。
中景に［ランドマーク］、小物として［手がかり］、遠景に次の舞台［予告］。
温かく精緻な児童書イラスト。人物、キャラクター、文字、ロゴ、UIなし。
16:9または使用箇所に合わせた超横長構図。
```

### 素材レビュー

- 主人公の足が道に接地して見えるか。
- 左端と右端でも主人公の全身とUIが読めるか。
- この土地・この話である理由を小物一つ以上で説明できるか。
- 前話から来た方向と次話へ進む方向を想像できるか。
- 案内役やアイテムを後から重ねる余白があるか。
- 色覚差や小画面でも道と背景を区別できるか。
- 異変中と解決後の差が一目で分かるか。

## 9. UIとアクセシビリティ原則

- ユーザー選択画面は「誰が遊ぶか」と新規作成への入口だけを扱う。
- 冒険者設定画面は、プレイ中ユーザーの名前、学年、キャラクター変更に集中させる。新規作成フォームは置かない。
- ステージ選択画面の主操作はステージ選択と開始だけにする。学習記録、図鑑、グレード、保護者向け画面は補助メニューへまとめる。
- タイピング基礎は本編と同じ一覧に一つのステージとして表示し、内部の練習は「ルート」と呼ぶ。
- 選択状態は枠、背景、文言、短い動きで伝える。色だけに依存しない。
- ストーリー本文と入力対象を同時に大量表示しない。
- 目的は短い一文で常に確認できるようにする。
- キャラクター、イベント吹き出し、進捗表示を左右端で重ねない。
- 色だけで成功、失敗、進捗を伝えず、形、動き、文言も併用する。
- 強い点滅や大きな画面揺れに頼らない。
- 古いiPadでも動くよう、常時動くレイヤーと粒子数を抑える。
- 音を消しても試練の予兆と解決が分かるようにする。

### 音

- ユーザーやステージの選択時には、短い決定音で操作が受理されたことを伝える。
- タイピング本編では、ゲーム開始感を出すため低音量の簡単なループBGMを流す。
- BGMと効果音は共通のサウンド切替で停止できるようにする。
- 外部音源がなくても動作できる軽量な合成音を基本とし、音が再生できない環境でも進行を妨げない。

## 10. 変更管理

新しい仕掛けを提案するときは、次を記録する。

1. 対応する学年・話と、ストーリーバイブル上の出来事。
2. プレイヤーが何をタイピングするか。
3. 入力によって画面上で何が変わるか。
4. 通常問題とクライマックスの違い。
5. ミス、離脱、再挑戦時の挙動。
6. 低学年、苦手な利用者、古い端末への配慮。
7. 必要な背景、状態差分、動物、アイテム、エフェクト、音。
8. ストーリーの正史を変更する場合、ストーリーバイブルも更新したか。
