# Stage 1〜36 連続3D世界 制作対応表

最終更新: 2026-08-10
状態: 制作設計。Stage 2〜12のグレーボックス／素材制作前
対象: 全6章・Stage 1〜36の制作資料。実制作・実装はStage 1〜12まで

## 1. 本書の役割

Stage 1〜36を独立背景として作らず、一つの島を歩き続ける連続コリドー型世界として制作するための全体対応表である。直接仕様は [第1〜2章ブリーフ](3d-stage-2-12-production-briefs.md)、[第3〜6章ブリーフ](3d-stage-13-36-production-briefs.md)、Stage 1は [草原から森の制作ブリーフ](3d-scene-brief-meadow-to-forest.md) を正とする。

**制作ゲート:** 今回、資料はStage 36まで完成させるが、モデル、素材、HTML技術検証、ゲーム実装を進めてよいのはStage 1〜12だけである。Stage 13〜36はStage 1〜12の空間・チャンク・BGM・発見演出が承認されるまで資料として保持し、制作へ着手しない。

物語は [ストーリーバイブル](story-bible.md)、ゲーム体験は [ゲームデザイン](game-design.md)、座標・チャンク・ストリーミングは [3D連続世界アーキテクチャ](3d-continuous-world-architecture.md) を優先する。

## 2. 絶対条件

- `worldProgress` はStage 1開始から36終了まで単調増加し、問題、コース、ステージ、章の終了で戻さない。
- ステージ終了時にscene再生成、canvas再マウント、背景交換、暗転、ポータル、通常移動中のクロスフェード、ページ再ロードを行わない。
- ステージは空間を所有しない。`regionId` と複数の `chunkId` にまたがる旅程範囲と物語イベントだけを所有する。
- 前ステージ終端と次ステージ始端は同じ共有境界チャンクを参照する。両側が別形状を複製してはならない。
- Stage 6→7も雲上遺跡から草原へ物理的に降りる。章変更をワープの理由にしない。
- Stage 7〜12はStage 1〜6と同じ六地域を再訪するが、同じ経路を逆再生しない。前章で回復した花・水路・根・空路を残し、隣接する別の細道を通る。
- BGMはステージごとに曲を頭出ししない。共有拍・和声の上で意味区間ステムを遷移させ、完了音は重ねる。

### 2.1 全36 Stageの地学・生態・文化契約

- 世界は古い低緯度玄武岩火山島で、北西山地は旧カルデラ縁・岩脈帯。東北東卓越風に対し北東斜面は多雨、南西は穏やかな雨陰となる。
- 弧状分水嶺から、森支流・星見支流・根泉支流が南側のことば川流域へ集まり、湾北部へ下る。route、谷、テクスチャ上の水路はこの高低を逆転させない。
- 入り江は北の河口湿地→中央の砂泥・海草藻場→南〜外湾の白砂ポケット浜・珊瑚裾礁→岬の海食洞である。全入り江を白砂・珊瑚にしない。
- 植生は風下低地草原→低地の亜熱帯常緑・半常緑林→山地雲霧林→風衝低木・草地へ連続する。雲上は恒常雪でなく霧氷・地衣・風成低草を使う。
- 雲上遺跡は自然山頂でなく、古代樹とカルデラ岩をアンカーにした人工・生物構造物。root–skyは螺旋回廊、sky–meadowは実体下降路でつなぐ。
- 球面座標から得る`routeDistanceKm`を地図と3D worldの唯一の距離正本にする。空間短縮、途中skip、teleportを行わず、chunk streamingで全routeを連続保持する。カメラの見える前進速度を不自然に上げず、景観anchor・境界・発見beatへ十分な短文問題とcourseを割り当てる。
- 集落は草原の風下小屋、森の高床小屋、山の低い石造観測所、湾の高潮線上高床、古代樹の独立根棚、雲上の共同管理施設とし、建材・生業を各地の風、水、岩、植生へ結びつける。
- 動物は`定着種 / 広域利用種 / 人と暮らす個体 / 来訪する仲間 / 文化上の島型`に分類する。大型獣の群れを17km島の野生相として増やさない。

各Stage制作データは最低限`geology / soil / drainage / prevailingWind / vegetationBand / settlementTrace / faunaResource / routeDistanceKm`を持つ。詳細は [地学・気候設計](world-geology-and-climate-spec.md) と [植生・生物・文化設計](world-biomes-fauna-culture-spec.md) を正とする。

### 2.2 距離から問題密度を決める契約

`5 course × 3問 = 15問`はStage 1の初期UI検証値であり、全36の固定仕様ではない。制作時はStageごとに次の暫定式で必要問題数を見積もり、実歩行QA後に増減する。

```text
Qdistance = ceil(routeDistanceM / 150)
Qbeats = 3 × (scenicAnchorCount + discoveryBeatCount + boundaryBeatCount)
targetQuestions = clamp(max(18, Qdistance, Qbeats), 18, 60)
targetCourses = ceil(targetQuestions / 8)   // 1 course 6〜9問を目安
```

- 各六コマanchorの前・最中・後に最低一問ずつ置き、景観変化を入力中に飛び越さない。
- 動物・アイテム予兆、物語解決、共有境界には専用の短文beatを割り当てる。
- 長い移動区間は同じ文を水増しせず、到着・観察・照合・解決・余韻の短文群へ分ける。
- Stage途中のcourse境界は保存・休憩点であり、カメラ、`JourneyWorld`、BGM拍位置を戻さない。
- 60問を超える見積りは速度を上げて解決せず、Stage内の休憩course追加または球面route設計そのものを再レビューする。

### 2.3 景観anchorの地形リズム契約

各Stageの既存六コマを最低六つの`scenicAnchor`として、色替えでなく地学由来のmicro-landformへ固定する。距離を稼ぐために同じ木、同じ道、同じ構図を反復しない。

| 地域 | 使用できるmicro-landform例 |
|---|---|
| 草原 | 溶岩原の緩丘、浅い涸れ沢、河岸段丘、季節湿地、防風林縁、海風を受ける支尾根 |
| 森 | 小川氾濫原、段丘崖、支流合流、倒木ギャップ、谷頭、岩脈露頭、雲霧林への肩 |
| 山 | 鞍部、支尾根、谷頭、岩脈岩塔、崩積斜面、風衝地、源頭湧水、折返し尾根 |
| 入り江 | 河口湿地、自然堤防、砂泥干潟、海草藻場、海岸段丘、ポケット浜、波食棚、礁縁、海食洞 |
| 古代樹林 | 溶岩洞崩落窓、宙水泉、根際湿地、古土壌段、洞内露頭、根の橋、月光ギャップ |
| 雲上 | 上昇根の風陰、霧氷石段、風衝露台、雲霧集水溝、石造鞍部、下降尾根アンカー |

各anchorは制作データに`microLandform / geologyReason / deltaFromPrevious`を持つ。`deltaFromPrevious`では、視界の開閉、上り下り、水の有無・流れ、岩の露出、植生帯、landmark、光の七軸から最低二軸を前anchorと変える。同じ二軸の組合せを二回連続させず、遠景→境界混在→内部の連続出現を守る。背景交換、暗転、霧の全面覆いで差を作ってはならない。

問題数算定の`scenicAnchorCount`にはこの六つ以上を用い、anchor間に到着・観察・変化の短文を十分配置する。六コマ画像の合否だけでなく、anchor間を通常速度で通した動画で「前へ進んだ」と読めることを承認条件にする。

## 3. 世界トポロジー

```text
南東の草原
  → 林縁・木漏れ日の森
  → 小川源流・星見の山道
  → 谷川・河口湿地・藻場・外礁・珊瑚の入り江
  → 海蝕洞の根道・月影の古代樹林
  → 古代樹の上昇根・雲上遺跡
  → 風の階段・尾根下降路・草原（別の丘）
  → 風抜けの森
  → 風見尾根
  → 海風の入り江
  → 古代樹の送風根
  → 天空の大風車
```

山の水が森・草原を通って入り江へ注ぎ、古代樹の根が入り江から全地域の地下へ続き、雲上遺跡からの光と風の階段が地上へ降りる、という正史の地理を接続根拠とする。

## 5. worldProgress / region / chunk契約

Stage境界は値をリセットせず、全36ステージを整数区間として扱う。

```ts
type StageJourneyRange = {
  stageId: `stage-${number}`
  worldRange: readonly [number, number] // 例: Stage N = [(N-1)/36, N/36]
  regionTrack: readonly RegionBlendKeyframe[]
  chunkSequence: readonly string[]
  eventTrack: readonly JourneyEventRef[]
  musicZones: readonly MusicMeaningZone[]
}
```

- `stageProgress` はUI表示と問題配分の派生値であり、カメラの正本ではない。
- クリアダイアログ中も現在チャンクとカメラを保持する。次へ進むと同じworldを再開する。
- 再挑戦時だけ保存済みstage開始座標へ移動できる。その場合も同じ`JourneyWorld`を保ち、必要チャンクをストリーマーが入れ替える。
- Stage 1〜12用のチャンクIDは将来の36ステージでも衝突しない土地名ベースにし、`stage-2-scene`のような所有名を避ける。

## 6. 共有境界チャンクの責務

| 境界 | 混在させる要素 | 境界でしてはいけないこと |
|---|---|---|
| meadow–forest | 短草→落葉、花→低木、若木→成木、暖空→青緑霧 | 木の壁、地表色の線、森背景カード |
| forest–mountain | 湿林床→乾土、成木減少、低木・岩増加、小川源流、遠山proxy | 橋の対岸で森を切る、突然海を見せる |
| mountain–inlet | 尾根→谷川、岩稜→海食岩、高山草→耐塩草、遠い海→水際 | 山頂直後に浜、海面の矩形端 |
| inlet–root | 白砂→湿土、波食洞→根の洞、珊瑚色→月白、潮霧→根の光 | 洞窟暗転、根門ポータル |
| root–sky | 巨根→上昇根、月光→雲光、発光植物→空中庭園、水路の連続 | エレベータ暗転、雲による全面隠し |
| sky–meadow | 白石→風化石→岩→草、雲海→地上靄、花びらの下降 | 落下演出、ロード用の白飛び |

## 7. 制作順序とゲート

1. `meadow-to-forest-threejs-v1.html`でチャンク分割、生成・解放、Stage境界保持を技術検証する。
2. Stage 1の見た目を保ったまま、`現在＋前方`チャンクで継続できることを確認する。
3. Stage 2「森→山」を六コマのグレーボックスで制作し、Stage 1終端と座標・植生・光が一致するか承認する。
4. 以後は一度に一境界を追加する。六地域を同時に品質制作しない。
5. Stage 6→7の下降回廊まで到達して、章をまたいでもsceneが継続することを技術ゲートにする。
6. Stage 7〜12は前章の結果が残る再訪差分として追加する。
7. Stage 12を承認した時点で実制作を止め、Stage 13〜36へ自動展開しない。
8. 空間承認後、アイテム予兆を一種類だけ試作する。アイテム個別3Dモデルの量産はしない。
9. BGMは意味区間イベントの出力だけを先に用意し、曲・ステム制作はStage 1試作承認後に行う。

## 8. 共通受入基準

- 各Stageの六コマが専用ブリーフの空間役割を満たす。
- Stage境界の前後で同じランドマーク位置、地形高、道中心、光、霧が連続する。
- 一文・コース・Stage・章の終了でカメラが戻らず、canvasが置換されない。
- 次地域が遠景→境界混在→内部の順で現れ、背景交換に見えない。
- 道は1.5〜2.5mの踏み跡を基本とし、中央にも苔・落葉・草切れが戻る。
- 地形とテクスチャ上の道中心が一致し、カメラ高は地形へ追従する。
- 発見予兆とBGMがなくても進行方向と物語結果を視覚で理解できる。

## 9. 動物発見候補（制作前仕様）

各Stage最大一種、発見イベント中だけ出す。案内役の常設表示ではなく、生態的に自然な距離と遮蔽物から一度だけ気配を見せ、タイピング成功後に2D図鑑報酬へ接続する。アイテム予兆は「静止物へ集まる柔光」、動物予兆は「足跡・食痕・枝草の局所反応・一時シルエット」として識別する。音OFFでは必ず視覚予兆を併用し、`reducedMotion`では揺れと逃走を短い姿勢変化＋フェードではなく遮蔽物への低速退避に置換する。
