# UI漢字ルビ監査

## 方針

- 問題文用の `RubyPhrase` / `ProgressRuby` は、問題データの `[表記:よみ]` を正本として継続利用する。
- 一般UIは `UIRuby` と共通読み辞書を使う。辞書の最長一致で語句単位の `ruby` / `rt` を生成し、UI上の漢字は用途や出現回数にかかわらず省略しない。
- 読み上げは外側の `aria-label` を一度だけ読ませ、視覚用のルビ列を `aria-hidden` にする。`rt` の二重読みを避ける。
- `rt` は本文の46%以上かつ7px以上、短いline-heightとし、1024×768の主要プレイ画面を押し広げない。長い詳細だけ内部スクロールを許可する。
- 主要説明文は12px相当を標準とし、補助情報でも原則11px未満にしない。本文line-heightは約1.5。文字を小さくして収めず、重複文言・余白・シーン高を先に圧縮する。
- 固有名詞や文脈で読みが変わる語は、単漢字の推測読みを追加せず、語句単位で辞書登録する。

## 監査結果

`rg -n "[一-龯々〆ヶ]" src --glob '*.{tsx,ts}'` では、コメント・データ・aria-onlyを含め329行が該当した。

分類:

1. 問題本文: 既存の問題データルビで対応済み。
2. 主要プレイ動線: タイトル、タイピングカード、クリア画面、基礎練習、ステージHUD。
3. 学習・収集画面: 問題一覧、図鑑、グレード、学習記録。
4. 設定・管理画面: ユーザー作成、設定、保護者向け画面。
5. 動的データ: ステージ名、物語、報酬名、ランク名。正本データへ読みフィールド追加が必要。
6. 非表示文字列: `aria-label`、テスト説明、ログ、コメント。視覚ルビの対象外だが、読み上げ文として自然か別途確認する。

## 第一配信単位

- 共通 `UIRuby`、読み辞書、未登録漢字検出関数、辞書テスト。
- タイトル／ステージ選択の固定ラベル。
- タイピングカードの操作案内と結果欄。
- ステージ／コースクリア画面の主要結果と主ボタン。
- 問題本文は既存 `ProgressRuby` を維持。

## 残件

- `KanaPracticePage`: 指名以外の見出し、コース説明、完了画面を共通基盤へ統合。
- `CourseMap`、`GameSidePanel`、冒険シーンHUDの全固定ラベル。
- `CollectionPage`、`CatalogPage`、`RankGuidePage`、`ProfilePages`、`ParentReportPage`。
- `KeyboardLayoutCalibration` の全説明・ボタン。
- `storyConfig`、`rewards`、`ranks`、`courseConfig` の動的表示名へ読みデータを追加。
- 主要画面ごとの1024×768 `scrollHeight <= clientHeight`、または主操作が初期viewport内にあることの継続計測。

## 静的検査

`getUncoveredUIKanji()` は `UIRuby` に渡す主要ラベルの未登録漢字を検出する。第一配信単位はテスト配列で裸漢字ゼロを保証する。全srcの自動検出は、データ・コメント・aria-only・既存問題ルビを除外できるAST検査へ拡張してから必須化する。
