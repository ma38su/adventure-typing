最終更新: 2026-08-09

## 1. この文書の役割

本書は、ことば島のBGMを場当たり的に増やさず、物語、景観、タイピング体験と一体で設計するための制作計画である。今回の制作対象は第1ステージに対応する1曲の試作までとし、残りの土地や全36話の曲は制作しない。

正本の優先順位は次の通り。

1. `docs/story-bible.md`: 世界観、地理、物語上の正史
2. `docs/game-design.md`: タイピング体験、音、アクセシビリティ
3. `docs/3d-scene-brief-meadow-to-forest.md`: 第1区間の承認済み画面仕様
4. `docs/watercolor-renderer-implementation.md`: 旅座標、区間、レンダラー実装検討
5. 本書: BGMの制作手順と第1曲の設計候補

参考画像は `artwork/preproduction/meadow-to-forest-storyboard-nihonga-simplified-v1.png` を第1曲の直接の視覚基準とする。既存の `bgm-preview.html` と `src/App.tsx` の合成BGMは比較用の技術試作であり、承認済みの曲ではない。

## 4. 第1ステージの曲設計候補

### 共通する物語・画面上の根拠

- 旅は南東の明るい草原から始まり、森へ入り、小川手前へ至る。同じ空間を歩き、背景交換や暗転を使わない。
- 草原は出発、観察、最初の手がかり。森は情報収集、最初の協力、次の土地への分岐である。
- 基本トーンは安心感のある冒険。危険や恐怖を音楽の中心にしない。
- 画面は広い空、花、若木、成木通過、5層の森、小川の青緑へ連続変化する。
- プレイヤーの中心行為はタイピングであり、音楽の変化を追わせるゲームにはしない。

### 案A「木漏れ日の先へ」— 推奨

| 項目 | 設計 |
|---|---|
| 感情曲線 | 草原の安心と小さな期待 → 林縁で少し寂しく不思議 → 森に包まれる安心 → 水音の気配と前向きな発見 |
| 勢い | ゆったりした歩行感。静かに始まり、後半で音数ではなく和声の開きと高音色で冒険感を少し増す |
| 世界観 | 簡略化した日本画、透明水彩、児童書ファンタジー。素朴だが幼児向けには寄せすぎない |
| テンポ・拍子 | 76〜82 BPM、4/4。8分音符を埋めず、4分音符中心で呼吸を残す |
| 主な音 | 柔らかいピアノまたはハープの疎な分散音、息の多いフルート、薄い弦の持続、木の響きを思わせるごく軽い打音 |
| 調性感 | 長調一色にせず、add6/add9、sus2、相対短調の陰りで「少し寂しいが前向き」を作る。終止を強く閉じすぎない |
| 尺・ループ | 本番候補48〜64秒。試作は48秒以上を1ループ。頭尾の環境的な余韻を共有し、3周で継ぎ目を評価 |
| 区間変化 | 基礎伴奏は全区間を連続。林縁でフルートの断片、森で薄い弦と低い木質音、小川前で高いハープ倍音を加える。曲そのものを交換しない |
| 避けること | 常時鳴る細かいアルペジオ、明るすぎる行進、勇壮な金管、重い低音、鳥声の写実的な多用、強いドラム、短い旋律の反復 |

この案は、絵コンテの余白と水彩の柔らかさ、物語の「安心できるが先へ行きたくなる」を最も直接的に表現できる。打鍵音のある中高域を常時埋めず、タイピングへの集中を保ちやすい。

### 案B「風のあとをたどって」

| 項目 | 設計 |
|---|---|
| 感情曲線 | 草原の好奇心 → 風に導かれる軽い高揚 → 森の奥で静かな集中 → 橋を見つける小さな達成感 |
| 勢い | 案Aより軽快。ただし疾走ではなく、一定のそよ風が背中を押す感覚 |
| 世界観 | 水彩の風景に、渡り便や言葉を運ぶ風のモチーフを薄く重ねる |
| テンポ・拍子 | 88〜94 BPM、6/8。大きな2拍で感じ、細かな伴奏を前面へ出さない |
| 主な音 | ナイロン弦または撥弦系の柔らかな音、クラリネット／アルトフルート、薄い弦、シェイカーではなく擦れる葉のような低密度ノイズ |
| 調性感 | 開放5度と短い上行モチーフ。森で一度内向きになり、小川前で長6度の響きへ開く |
| 尺・ループ | 48〜64秒。2小節の上行モチーフを毎回鳴らさず、4〜8小節空けて再登場させる |
| 区間変化 | 草原では撥弦、林縁で木管、森で持続音、小川で上行モチーフを回帰。進捗停止時も拍と曲は継続する |
| 避けること | ケルト音楽など特定文化への表層的な寄せ、踊りのような強い6/8、可愛すぎるピチカート、風音で打鍵を覆うこと |

案Bは冒険の推進力を感じやすい一方、6/8の動きがタイピングのリズムへ干渉する可能性が案Aより高い。そのため比較対象として残し、最初の本制作候補にはしない。

## 5. 推奨案と最初の1曲試作

推奨は案A「木漏れ日の先へ」とする。最初の試作は全ステージ版ではなく、第1区間の方向を判断できる最小限に限定する。

### 試作範囲

- 48〜64秒のシームレスな1ループ
- 草原を基礎状態とし、林縁、森、小川の3つの追加レイヤーを同じ拍・同じ和声進行で重ねられる構成
- まずはMIDIまたは仮音色でもよいが、ピアノ／ハープ、木管、弦の役割と密度を判断できる音色を使う
- 通常タイピングと正打鍵・誤打鍵・問題完了の効果音を重ねた比較試聴
- 10秒デモへの同期は音楽性の検査に使わない。10秒映像では区間レイヤーの変化だけを仮確認する

### 必要成果物

1. 試聴用ステレオ音源: WAV、48 kHz、24 bit
2. 実装確認用ループ: OGGまたはWebM/Opus、およびSafari系互換性確認用AACまたはMP3候補
3. ステム: `base`、`melody`、`forest-color`、`creek-glint` の4系統を第一候補とする
4. ループ点、BPM、拍子、曲尺、キュー位置を記した短い仕様メモ
5. 効果音併用版の試聴ファイル
6. 制作元データ、使用音源・ライセンス一覧。外部素材がなければその旨を記録

実装形式は試作評価後に、iPad/Safariの実機再生、デコード負荷、ループ精度を確認して確定する。試作段階で一形式へ固定しない。

### 評価チェックリスト

- 3周連続で聴いてループ境界が注意を引かない。
- 30秒以上タイプしても旋律の反復が入力を急かさない。
- 正打鍵音が埋もれず、誤打鍵音が過度に鋭く感じられない。
- 草原から森へ、曲を交換せず空気が少し深くなったと感じる。
- レイヤー変化を意識しなくても、画面と音の違和感がない。
- 「少し寂しいが前向き」「怖くない不思議さ」が両立する。
- 小川前で達成音のように完結しすぎず、旅の続きを予感できる。
- 子どもっぽすぎる、派手すぎる、映画予告風、環境音過多になっていない。
- 小型スピーカーとヘッドホンの両方で低音が邪魔にならない。
- ミュートしてもゲーム上の情報が失われない。

### 承認ゲート

1. 本書の案A／案Bと推奨案をユーザーが確認する。
2. 推奨案の30〜45秒程度の構成スケッチ、または48〜64秒の粗い1ループを作る。
3. BGM単体、効果音併用、承認済み10秒映像との組み合わせを比較する。
4. 感情、テンポ、音色、密度、区間変化の5項目を調整する。
5. 方向承認後にのみ、正式なループ、ステム、実装形式を仕上げる。
6. 第1ステージの画と音が承認されるまで、残り5土地の詳細設計・作曲へ進まない。

## 6. 3D進行との連携

BGMは、背景ごとに別曲を常時クロスフェードする方式を前提にしない。第1区間では一つの曲の拍、和声、基礎伴奏を保ち、穏やかなステムの出入りで土地の空気を変える。これにより、タイピング速度の個人差や停止で音楽が不自然に継ぎ接ぎされることを避ける。

### 責務分離

| 入力・状態 | 音楽側での扱い |
|---|---|
| `journeyProgress` | ステージ全体で単調増加する入力。音楽制御層がレンダラーと同一の `routeMapping` を使って `cueProgress` へ変換する候補がある。曲の再生位置を直接シークしない |
| 空間位置 `s` | 草原、林縁、森、小川という空間区間を定義する唯一の座標。BGM本体は生の `s` を原則参照せず、音楽制御層で変換された `cueProgress` またはレンダラーが提供する意味的な区間量を受ける |
| `isTyping` | BGMの再生／停止や旅の位置に使わない。必要なら極小の環境反応に限定するが、初回試作では連動なしを標準とする |
| `typingPace` | テンポ、再生速度、曲の進行を変えない。試作ではBGM非連動。将来使う場合も装飾量のごく狭い範囲に限定する |
| 文区切り | 曲を先頭へ戻さない。問題完了効果音のために瞬間的な音量余白を設けても、BGMの拍とループは継続する |
| 報酬・完了 | 短い効果音または別ジングルをBGM上へ重ね、必要ならBGMを緩やかに下げる。区間BGMの再起動はしない |

空間上の区間キュー目安は、`s` を基準として草原 `0.00〜0.20`、林縁 `0.20〜0.55`、森 `0.55〜0.82`、小川への接近 `0.82〜1.00` とする。これらは `journeyProgress` の境界値ではない。

本番の接続候補は次のいずれかとする。

1. 音楽制御層が `journeyProgress` をレンダラーと同一の `routeMapping` で `cueProgress` へ変換し、`cueProgress` を `s` 相当の正規化位置としてレイヤー量へ写像する。
2. レンダラーまたは共有の旅制御層が、`meadow`、`forest`、`creekApproach` など意味的な区間量を0〜1で算出し、BGMへ渡す。

どちらの場合も、区間境界、混合曲線、`routeMapping` の定義は共有し、BGMだけが独自の境界値や速度曲線を持つことを禁止する。境界ではレイヤーを瞬時にオン／オフせず、共通定義に基づく十分な混合幅を持たせる。

初回試作ではこのリアルタイム連携を実装しない。10秒映像上で共有区間を使った仮のレイヤー変化を確認するだけとし、映像の10秒アンカーへ音楽の小節境界を固定しない。

## 7. 著作権とオリジナル化

参考曲は雰囲気を伝える資料としてのみ扱い、旋律、コード進行、特徴的なリズム、編曲、音色の組み合わせを再現しない。「静かな始まり」「木管の透明感」「この程度の緊張」「余白の多い伴奏」など抽象的な機能へ分解し、物語、絵コンテ、タイピング可読性から新しい旋律と構成を作る。

制作時は、作曲者、制作日、使用ツール、外部音源、ライセンス、生成AI利用の有無と条件を記録する。第三者の曲を学習用・仮当て用に使う場合もリポジトリや配布物へ含めない。

## 8. 制作順と今後のキュー

1. 第1ステージの正本画像、物語、3D区間を確認する。完了。
2. 本書の共通設計表と第1曲2案をレビューし、推奨案を承認または修正する。
3. 承認案で最初の1曲を粗く試作する。
4. BGM単体、効果音併用、3Dデモ併用で方向を調整する。
5. 承認後、第1曲のループ、ステム、実装形式を仕上げる。
6. 第1ステージ完成後に、共通テンプレートを使って次の土地を一つずつ設計する。

この順序の間、3D側は区間キューを渡せる責務分離を念頭に置くが、BGM都合で旅座標やカメラを変更しない。BGM側も、レンダラーのグレーボックス承認を待たずに全土地の曲を作り始めない。

次の承認ポイントは、案Aの「76〜82 BPM、4/4、疎なピアノ／ハープ、息の多い木管、薄い弦、後半は和声とレイヤーで冒険感を増す」という方向で、最初の音の試作へ進んでよいかである。
